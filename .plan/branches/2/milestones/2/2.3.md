# Issue 2.2.3: Add flipbook check and gate show and export

**Branch:** [2 — Deck blueprint](../../README.md)
**Milestone:** [2.2 — Content rules and check](README.md)
**Description:** `bin/flipbook.js` gains a `check` command. `show` and `export` call the same validation when `blueprint.yml` is present, so a failing deck is not served and is not exported.
**Tests:** required

## Tasks
- [ ] Task 2.2.3.1: Add `flipbook check [path]`
  **Acceptance criteria:**
  - A deck with no `blueprint.yml` exits 0 and prints that it has no blueprint
  - A deck that matches its blueprint exits 0 and prints the slide count
  - A deck that breaks order or content exits with code 1
  - stderr lists every violation, one per line, each with the slide path or index
  - `flipbook --help` documents `check`
- [ ] Task 2.2.3.2: Refuse `show` and `export` when the blueprint fails
  **Acceptance criteria:**
  - `show` does not start the server when validation fails
  - `export` does not write PNG files when validation fails
  - A deck with no blueprint still shows and exports as it does today
  - A passing blueprint leaves `slide.template` filled from the type when the author omitted it
- [ ] Task 2.2.3.3: Write tests for check and the show/export gate
  **Acceptance criteria:**
  - Tests cover exit success, exit failure with a conclusion over 250 characters, a missing blueprint, and `show` throwing before `startServer`
  - Export can be asserted by a function that validates before rendering, without launching Chromium
  - `npm test` passes
