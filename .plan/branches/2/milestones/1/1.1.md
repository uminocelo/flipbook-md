# Issue 2.1.1: Load blueprint.yml

**Branch:** [2 — Deck blueprint](../../README.md)
**Milestone:** [2.1 — Blueprint file and page types](README.md)
**Description:** Read an optional `blueprint.yml` from the deck root (`loadDirectoryProject` root, or the directory of a `*.slide.md`). Absence is success and means "no rules". A present file must be a YAML object with `pages` and `types`.
**Tests:** required

## Tasks
- [ ] Task 2.1.1.1: Parse `blueprint.yml` into pages and types
  **Acceptance criteria:**
  - A missing `blueprint.yml` yields no blueprint
  - A file with `pages` (ordered type steps, each with optional `repeat` as a number or `{ min, max }`) and `types` (map of type name to rules) loads
  - Each type may set `template`, `max_chars`, `allow`, and `forbid`
  - A page step may set `max_chars`, `allow`, and `forbid` to override that type for the step
  - A non-object file, a missing `pages` list, an empty `pages` list, or a type name that is not `[a-z][a-z0-9-]*` throws and names `blueprint.yml`
  - A type `template` other than `flow`, `cover`, or `summary` throws and names `blueprint.yml`. Branch 4 adds deck-defined names to this set
- [ ] Task 2.1.1.2: Write tests for blueprint loading
  **Acceptance criteria:**
  - Tests cover a missing file, a valid talk blueprint, a page-level override, and a malformed file
  - The valid fixture includes a `conclusion` type with `allow: [heading, paragraph]` and `max_chars: 250`
  - `npm test` passes
