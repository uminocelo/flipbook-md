# Issue 1.2.1: Apply the template in the player

**Branch:** [1 — Slide templates](../../README.md)
**Milestone:** [1.2 — Player and export](README.md)
**Description:** `public/app.js` paints `slide.html` inside `.slide-root`. Wrap that HTML in `.slide-body`, set `data-template` from the API, and add grid rules to `public/slide.css`. The deck-title eyebrow stays a sibling before `.slide-body`. Controls in `public/styles.css` stay as they are.
**Tests:** required

- [x] Task 1.2.1.1: Set `data-template` and wrap slide HTML in `.slide-body`
  **Acceptance criteria:**

  - Author Markdown is inside `.slide-body`
  - The injected deck-title eyebrow remains outside `.slide-body`
  - A `flow` slide still shows the title, body, and lists
- [x] Task 1.2.1.2: Add 3×3 grid rules for `cover` and `summary` in `public/slide.css`
  **Acceptance criteria:**
  - `cover` places `.slide-body` in the center cell, with the text centered in that cell
  - `summary` places `.slide-body` in the lower-right four cells
  - `flow` does not become a grid; existing element rules for `h1`, `p`, `li`, `pre`, and `img` still apply inside `.slide-body`
  - The grid fills the slide surface (`:host` / `.slide-root` have a used height inside `#slide`)
  - Rules are under `@layer base` so `presentation.css` can restyle a known template
- [x] Task 1.2.1.3: Write tests for the player template contract
  **Acceptance criteria:**
  - A test reads `public/slide.css` and finds the cover and summary placements
  - A test reads `public/app.js` and finds `data-template` and `.slide-body`
  - `npm test` passes
- [x] Task 1.2.1.4: Verify cover and summary in the browser player
  **Acceptance criteria:**
  - A fixture deck with one `cover` slide and one `summary` slide is served with `flipbook show`
  - On a desktop viewport, cover content sits in the center of the slide and summary content sits in the lower-right of the slide
  - Arrow keys still move between those slides
  - A `flow` slide in the same deck keeps a top-aligned document stack
