# Issue 1.1.2: Parse template from a slide

**Branch:** [1 — Slide templates](../../README.md)
**Milestone:** [1.1 — Template model](README.md)
**Description:** Read the template while `normalizedSlide` in `src/presentation.js` already runs gray-matter. Directory slides may use YAML frontmatter. Both directory slides and `---` separated slides in a `*.slide.md` file may use an HTML comment. The comment must not survive into `slide.html`.
**Tests:** required

## Tasks
- [ ] Task 1.1.2.1: Read `template` from frontmatter and from `<!-- template: name -->`
  **Acceptance criteria:**
  - A directory slide with `template: cover` in frontmatter loads `slide.template === "cover"`
  - A slide whose body starts with `<!-- template: summary -->` loads `summary`, in both `loadDirectoryProject` and `loadSingleFile`
  - The comment is absent from `slide.html`
  - When frontmatter and the comment disagree, frontmatter wins
  - A slide with neither is `flow`
  - `template: poster` (or any unregistered name) rejects the load and the error includes the slide number and the name
- [ ] Task 1.1.2.2: Put `template` on the slide object returned to the server
  **Acceptance criteria:**
  - `loadSingleFile` and `loadDirectoryProject` include `template` on every slide
  - Existing title and html behavior is unchanged for a slide that does not set a template
- [ ] Task 1.1.2.3: Write tests for template parsing
  **Acceptance criteria:**
  - Tests cover frontmatter, the HTML comment, single-file `---` slides, frontmatter winning over the comment, the default `flow`, and an unknown name
  - Tests live in `test/presentation.test.js` or `test/templates.test.js`
  - `npm test` passes
